# 青杉生活超市 · 新店开业筹备数智化平台（Demo V2）

> 基于《行业分析报告与项目方案》§2.3–§2.5「跨群依赖不可见」痛点做的可交互落地 Demo：三套互不相通的系统（装修 / 设备 / 商品）任务散落、店长每周 6 小时人工汇总仍看不全全景。
> 本平台用「只读试点」思路落地：**实时看板 + AI 依赖图谱 + 超时预警 + 安全硬闸门（消防/用电不代签）**。

## 技术栈

- **前端**：原生 HTML/CSS/JS（零构建）；实时协同部分用 **SSE（EventSource）**。
- **后端**：Node.js **零依赖** HTTP 服务（HTTP + SSE，无需 `npm install`）。
- **数据底座**：3 个形态各异的只读数据源，经适配器**归一化到统一「业务编号」主键**（对应报告 §2.4）。

## 目录

| 路径 | 说明 |
|---|---|
| `index.html` | 单文件静态 Demo（报告方案可视化，离线可用） |
| `public/` | 后端驱动的前端：登录 / 看板 / 依赖图谱 / 预警 / 审计 / 安全闸门 |
| `server/server.js` | 零依赖后端：HTTP + SSE 实时推送、鉴权、动作接口 |
| `server/db.js` | JSON 持久化 + 审计留痕 |
| `server/adapters.js` | 三系统只读适配器（归一化到 业务编号） |
| `server/data/extract_*.json` | 三个原始系统抽取样例（不同 schema） |

## 运行

```bash
cd qingshan-demo
node server/server.js            # 默认 http://localhost:8787
PORT=9000 node server/server.js  # 自定义端口
```

浏览器打开 http://localhost:8787 ，用演示账号登录：

- **店长** / `周店长`
- **区域总监** / `周总`（唯一可人工签核安全闸门）

首次启动自动从 `server/data/extract_*.json` 做一次三系统只读同步，无需预置数据库。

## 试试看

1. 切到「江南路店」：默认即典型事故态（电力增容逾期、生鲜被安全闸门拦截）。
2. 用「区域总监」登录，在「🛡 安全硬闸门」**人工签核电力增容** → 系统自动复盘并解除生鲜拦截，审计留痕同步记录。
3. 多个浏览器同时打开 → 一端操作，其他端毫秒级实时刷新 + 预警推送。

## 对应报告

|---|---|
